# Phase 1 交付报告

日期：2026-09-22。状态：已完成单场卡牌渡魂原型，等待开发者试玩与下一阶段确认。

更新：本报告记录第一版交付。之后按开发者要求完成手机横屏全屏UI重构；当前界面与测试结果以 [横屏界面修改与验收](phase-1-landscape-ui.md) 为准。

## 本阶段目标与结果

完成绯川面对测试亡魂的单场对局：30执念、3基础灯火、5张基础手牌、10回合上限。
起始牌组共12张，由6种公共牌组成；采用JSON数据驱动。当前无角色特性执行或专属牌效果。
界面包括中文卡牌、费用、亡魂执念、牌堆数量、操作记录、玩法说明、牌组构成、成功/未完成结算与重新开始。
占位素材由CSS和SVG绘制，游戏不依赖外部图片或字体服务。

## 文件与结构

- `src/data/`：人物、亡魂、卡牌与起始牌组JSON。
- `src/core/`：数据类型与校验、种子洗牌、通用卡牌效果、对局和回合、最小事件总线。
- `src/ui/battle-view.ts` 与 `src/style.css`：界面、输入、弃牌选择、结算弹层与适配。
- `tests/`：19项规则测试。
- `e2e/`：5项实际浏览器交互测试。
- `package.json`、锁文件、TypeScript/Vite/Vitest/Playwright配置：运行、构建与测试环境。
- `start-game.cmd` 与 `README.md`：本机启动与操作说明。
- `docs/asset-checklist.md`：素材规格和内容清单，无生成描述词。
- `docs/screenshots/`：实际运行的对局和成功结算截图。
- `build/`：可预览的生产构建结果。

## 关键规则

出牌先校验手牌归属、费用及弃牌选择，再结算；非法操作不改变对局状态。
整理行囊支持先选牌、取消或确认，取消无消耗。正在结算的卡牌暂存于Resolving区，不会被自己的抽牌效果抽回。
第10回合仍可正常出牌；结束该回合时执念尚存才失败。成功与失败后禁止继续操作，结束事件仅发一次。
新对局创建完整新状态；相同牌序编号与相同操作能够复现洗牌结果。
人物身份仅来自数据，Battle内没有绯川专用能力判断；CombatTrait与ResourceTrait字段暂为空，界面标明后续启用。

## 测试环境与已处理问题

Node.js 24.15.0，npm 11.12.1。依赖版本固定在package-lock.json。
独立测试浏览器下载超时，改用本机浏览器。Chrome测试运行时出现过进程退出和页面进程崩溃；Edge完整测试通过，因此测试默认使用Edge。
Windows环境出现输出目录删除后重建的EPERM错误。构建改用build目录并保留目录及旧哈希文件；本次输出以index.html引用为准。测试输出按运行编号隔离，关闭易受目录清理影响的跟踪录制。
修正浏览器测试的文本比较方式：对相同牌序与取消弃牌的前后显示使用一致的innerText比较，避免因DOM空白差异误报。

- 当前测试亡魂没有特殊行为、负面状态或剧情分支；因此没有加入净化卡。

- 构建保留旧哈希文件，正式部署阶段需补充打包清理流程；当前没有部署到公网。
- 未完成跨平台、Firefox、Safari、触屏与完整无障碍验收。
