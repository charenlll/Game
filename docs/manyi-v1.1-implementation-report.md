## 剧情接入

保留批准文件原文于 `docs/manyi-v1.1-source.md`。`scripts/build-manyi-content.py` 生成 292 个节拍（283 段正文、9 个遭遇），同时保留出场名单和战斗设计备注。六场战后均先执行现有净化表现，再发奖励，返回各自后续剧情。三条可选分支均有进入/跳过出口。

发布后节点ID与textKey属于存档契约。修改台词优先编辑本地化表中的值；不得直接全量重建并重编号已发布节点。结构调整必须保留旧节点或提供存档迁移，该脚本只作为首次导入工具。

## 卡牌、意图与解锁

| ID | 名称 | 当前规则 |
|---|---|---|
| common_007 | 周转 | 费用1，预先选择一张当前普通手牌，抽2张后弃置所选牌。使用现有手牌选择交互；不能选择新抽到的牌，卡面已明确说明。与0费弃2抽2的整理行囊存在取舍。 |
| common_008 | 清账 | 费用1，选择并移出手牌中的1张浊念，然后化解2点执念；无浊念时禁用并提示。 |
| feichuan_004 | 借势 | 费用1，获得1点灯火，本回合下一张普通牌额外化解2；与善贾联动，不递归触发。 |
| burden_003 | 虚账 | 无法主动使用/弃置；回合结束仍在手中时，每张复制1张到弃牌堆。活动牌堆内合计最多6张，消耗堆不计。 |
| intent_account_inflation | 账目膨胀 | 回合结束向弃牌堆加入1张虚账并恢复2执念，遵守复制上限。 |

固定①首次未解锁时仅奖励周转，固定②仅清账，固定③仅在绯川且未解锁时奖励借势。确认领取才永久解锁并加入当前局内牌组；不会自动改写局外配置。其他场次及已解锁关卡使用随机奖励。虚账实际进入战斗快照即记入牌录，不能构筑。

当前数值属于首轮可测配置，未视为最终平衡。流程浏览器测试使用调试胜负入口加速推进，因此不代表九场实际出牌难度已经人工验收。

## 初始牌组与存档

牌录增加编辑入口，支持增加/减少、重置默认、数量显示、未解锁状态及保存。保存前统一校验数量、同名上限、角色归属、永久解锁和浊念禁入。绯川默认12张，其余已解锁摆渡人使用9张通用牌作为合法回退配置。

旧档新增 `profile.unlockedCardIds`、`profile.startingDecks` 和 manyi 章节进度；不重写进行中的 RunDeck、手牌或战斗快照。重复加载幂等。第一章保存剧情节点、分支标志、奖励选项/选择、重试次数，以及完整战斗手牌/牌堆、回合、随机状态和意图游标。主动从设置返回驿站后，刷新仍停留驿站。

## 彩色对白与演出

序章仍使用原文本、节点和战斗顺序。第一章支持旁白、具名人物、画外音、场景切换、昼夜滤镜、道具占位、跳过确认、逐字显示和点击显示全文。出场名单用于保留双方人物，当前发言人物突出；无声旁白不需要音频。多名非绯川人物在左侧共用发言位置，正式人物美术缺失时使用明确的临时剪影。跳过对白仍提交经过节点的状态标记，持盈的“已遇见”档案不会因跳过而遗漏。

按照本次补充：两章对白区均透明且无边框；人物高度185%、顶部7%，保持原图比例，由实际窗口裁去画面外下半身，不能在中央逻辑舞台边界裁掉左右人物。背景、场景滤镜与确认遮罩独立覆盖实际视口。相关调整位于 `src/ui/prologue.css`、`src/ui/manyi.css` 与 `src/ui/viewport.ts` / `viewport.css`。

## 截图反馈修正：对白断边与牌组卡顿

- 原因一：故事背景、滤镜与人物仍被1600×900舞台边界裁切。修正为背景/滤镜/确认遮罩覆盖实际视口，人物只在真实窗口边缘裁切，文字和按钮继续使用原逻辑坐标。
- 原因二：PR1道具占位在正文区域重叠。移至画面上方独立道具区，与正文保留间隔。
- 原因三：编辑器卡面宿主缺少相对定位，绝对定位的卡牌内部层错误使用整个弹窗作为定位范围，造成大图、费用和描述叠在一起。补齐100×150缩略图定位及裁切容器。
- 增减/重置牌组仅更新编辑器，保留驿站场景、环境画布与滚动位置。八次连续增减的同步DOM更新时间约2.4～6.6ms；这是本机操作采样，不代表所有设备帧率。
- 验证：构建通过；第一章、序章和视口相关16项浏览器检查通过。包括1912×914（反馈截图比例）、1600×800、1280×720、932×430及1440×1000的相关覆盖检查。
- 已查看 `artifacts/fix-deck-editor-1912.png`、`fix-manyi-story-1912.png`、`fix-prologue-story-1912.png`，确认无中央舞台的左右竖向断边、道具不压字、缩略卡面不再跨出所属条目。
